How the tests run

  • Each test runs in a container with no network access, with the script mounted read-only.
  • Package and binary checks use the real package, pinned to an exact version.
  • Lockfile and source checks use sample files.
  • Expected results come from vendor advisories, distro security trackers and OSV, never from the script's own output.

Known limitations

  • In -c mode the script doesn't look inside an image's virtualenvs, node_modules or bundled libraries (test 62).
  • Distros other than Debian, Ubuntu and Alpine get WARN, because their patched builds keep the upstream version number.
  • macOS-only checks (Homebrew, otool) can't run in a Linux container, so the tests don't cover them.
