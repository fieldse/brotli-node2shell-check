HTTP2Shell: Brotli decoder CVE
Are you affected?

Attackers are exploiting a bug in Google's Brotli decoder that lets crafted compressed data crash a server, leak memory or run code, with no login. If your service runs on Node.js, Bun, Python, .NET, Java, curl or Envoy, you may be affected. Read here about how to remediate.

The bug

What it is
  • An out-of-bounds write in the decoder of Brotli, Google's compression library, versions 1.0.3 to 1.2.0 (CVE-2026-111497). Runtimes and packages use it to unpack Brotli-compressed HTTP data.
  • Fixed upstream in 1.0.10, 1.1.1 and 1.2.1, all released 2026-10-21.
  • Every runtime, package or library that bundles or links that decoder inherits it.
Impact
  • Remote code execution, memory leaks or crashes. The CVE record rates it 9.2 Critical (CVSS 4.0). Node.js and Microsoft rate it High.
  • Under active attack. CISA added it to its Known Exploited Vulnerabilities list on 2026-10-27.
  • No login needed. Any app that decodes attacker-supplied Brotli is reachable: a request body sent with Content-Encoding: br (Express 5, Koa body parsers, node:zlib) or a response fetched from a server the attacker controls (fetch(), Python urllib3, httpx, aiohttp). Clients are exposed as well as servers.
  • Code execution is proven on stock Node.js 24.22.0. Failed attempts crash the process, and each build needs its own offsets.
Names
  • Node2Shell: the flaw in the Node.js runtime, reached through Brotli request bodies.
  • HTTP2Shell: the flaw in any HTTP client or server that decodes Brotli, such as Python's urllib3, requests, httpx and aiohttp via the Brotli and brotlicffi packages. Unrelated to HTTP/2.
  • Python2Shell: the flaw in Python's Brotli and brotlicffi packages, which compile the same C decoder.
  • Brotli2Shell, Broccoli2Shell, Brotlipocalypse: names for the decoder flaw itself.
Exploitation
  • Attacks started within a day of disclosure. Vendor sensors have logged attempts from at least 20 IPs since 2026-10-21.
  • No confirmed compromise yet. ELLIO replayed a captured exploit chain 50 times in a lab and got no shell.
  • Public exploit code has been out since 2026-10-22.
Related
  • The pure-Go andybalholm/brotli has the same flaw, but in Go it can only crash the process. Fixed in v1.2.7. See the Go row.

  • Python wheels with their own Brotli: Pillow 13.0.0 wheels bundle libbrotli 1.2.0, and no fixed Pillow release exists yet. duckdb vendors an unfixed Brotli 1.1.0 decoder. The pip versions of these packages don't map to Brotli versions.
  • Distro-installed python3-brotli shows the upstream version even after patching. Use the OS row.
  • Java: jvmbrotli (com.nixxcode.jvmbrotli) is abandoned and bundles Brotli 1.0.7. Replace it.
  • Ruby: from 0.4.0 the brotli gem links the system libbrotli if libbrotli-dev was present at install. Those builds are fixed by the OS update.
  • Go cbrotli has no C code of its own. cgo links the build host's libbrotli, so patch the OS library and restart. Bazel builds compile @org_brotli from source, so move that to 1.2.1 and rebuild.
  • Rust: brotlic-sys bundles Brotli 1.0.9. compu-brotli-sys 1.2.1 and 1.0.10 bundle the unfixed 1.2.0 and 1.0.9 decoders despite their version numbers. Its only fixed release, 1.2.0, is yanked. Judge any other -sys crate by its vendored source: fixed code contains BROTLI_DECODER_ERROR_FORMAT_BLOCK_SWITCH. Grep Cargo.lock, because plain cargo tree shows only the host target.
  • Debian's nodejs package, and Ubuntu's on 22.04 and later, use the system libbrotli, so node --version alone tells you nothing there. Check the Debian / Ubuntu row. Ubuntu 20.04's nodejs 10.19 bundles its own Brotli and has no fix. Updating libbrotli1 doesn't cover it.
  • Debian bookworm has no fixed build for armel, mips64el, mipsel or s390x.
  • RHEL, AlmaLinux, Amazon Linux and SLE keep the old version number when they patch, so compare the full release string (e.g. 1.0.9-10.el9_8.1) against the vendor tracker, not the upstream version.
  • Bundled copies on RPM distros: some packages bundle their own Brotli and won't show in rpm -qa | grep brotli. These include Firefox, Thunderbird, the RHEL 8/9 nodejs:24 and nodejs:26 modules, and on SUSE ghostscript, qemu, ovmf, texlive and mozjs.
  • Scanners stay silent for several of these. Bun, Brotli4j, the Ruby gem, curl_cffi, andybalholm/brotli and the Rust -sys crates have no entry in the GitHub Advisory Database, OSV, the Go vulnerability database or RustSec. Dependabot, OSV-Scanner, govulncheck, bundler-audit and cargo audit won't flag them.
  • Containers: run the same checks inside every image you ship, for example docker run --rm --network=none <image> node --version (or podman run). Updating the host does not fix an image. Rebuild it.

Vendored Brotli source

If you vendor Brotli's C source, fixed code contains the error name BROTLI_DECODER_ERROR_FORMAT_BLOCK_SWITCH. This lists decoder files that lack it:

grep -rIlZ --include='decode.c' --include='decode.cpp' 'BrotliDecoderDecompressStream' . |
  xargs -0 -r grep -L 'BROTLI_DECODER_ERROR_FORMAT_BLOCK_SWITCH'

Copies older than 1.0.3 also show up but are not affected.

The Debian and Ubuntu security patches add the same error name. Compiled libraries show it as _ERROR_FORMAT_BLOCK_SWITCH (1.1 and later) or a bare BLOCK_SWITCH (1.0.x). Still judge OS packages by version.

Automated checker

Source on GitHub

We provide a free script that runs every check on this page against one machine in a single pass. With -c it also checks local Docker or Podman images. It reads files and makes no changes. Usage is in the repository README.

git clone https://github.com/fieldse/brotli-node2shell-check.git
cd brotli-node2shell-check
less scripts/vuln-check-CVE2026-111497-brotli.sh   # review before running

View the script source: vuln-check-CVE2026-111497-brotli.sh.

./scripts/vuln-check-CVE2026-111497-brotli.sh -r ~/src -q    # scan a source tree and report problems only
./scripts/vuln-check-CVE2026-111497-brotli.sh -r /srv -c     # also check local Docker or Podman images
./scripts/vuln-check-CVE2026-111497-brotli.sh -c -e podman   # set the engine (by default Docker, then Podman)
./scripts/vuln-check-CVE2026-111497-brotli.sh --help
FAIL
A known-vulnerable version is present.
WARN
Needs manual review.

The script exits 1 on any FAIL. With --strict it also exits 1 on any WARN, so it can gate CI.

If you can't upgrade today

Reject request bodies with Content-Encoding: br at your proxy or gateway. This doesn't protect code that fetches Brotli responses from user-supplied URLs, so upgrade as soon as you can.
